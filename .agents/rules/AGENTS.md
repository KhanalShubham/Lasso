## 1. Operating Rules for AI Coding Assistant (Antigravity)

### Rule 2: Inspect Existing Code and Files Before Editing
Always check what files, datasets, dependencies, and code actually exist using tools (`view_file`, `list_dir`, `run_command`). Never assume a file exists or has specific columns based purely on memory or a planned schema.

### Rule 3: Absolute Prohibition on Invention
- Never fabricate data, metrics, row counts, or experimental findings.
- Never claim a task or test is "Done" without executing the command and verifying the actual output.
- Never invent placeholder numbers or substitute unrelated variables without explicit user confirmation.

### Rule 4: Absolute Prohibition on Temporal Lookahead Leakage
- Never use post-match statistics (in-game goals, shots, possession, cards during the 90 minutes of the match being predicted) as candidate predictors.
- The rolling moving-average operator $\bar{X}_t^{(k)}$ strictly sums over matches $t - j$ where $j \ge 1$. Summing over $j = 0$ is a fatal methodological violation.
- Always sort fixtures chronologically by kickoff timestamp, never by nominal Gameweek round number or season-end tables.

### Rule 5: Raw Data Immutability
- Files located in `data/raw/` are strictly read-only and immutable.
- Never edit, clean, impute, scale, or overwrite raw files in place. All pipeline outputs must be written to `data/processed/` or `data/features/`.

### Rule 6: No Silent Modifications to Research Scope
- The competition (English Premier League) and temporal horizon (2019/20 to 2023/24, exactly 1,900 matches) are non-negotiable constants.
- Never modify the mathematical objective, parameterizations, solver specifications, or feature definitions without logging the change in [DECISIONS.md](file:///d:/MLE-Lasso/DECISIONS.md) and obtaining user approval.

### Rule 7: Reproducible Scripts & Explicit Data Contracts
- Every transformed dataset must be generated by a reproducible standalone script in `src/`.
- Maintain clean data contracts: enforce explicit column names, verified data types, and non-null guarantees across all intermediate tables.

### Rule 8: Gate Verification Before Completion

- Never skip a quality gate. A gate is passed only when its automated tests execute with code 0 and verifiable output files exist.
